# LLM на C++14 с нуля

Учебная реализация языковой модели современной архитектуры (Llama-style) без
внешних зависимостей. Цель — не догнать llama.cpp по скорости, а разобраться,
из чего состоят современные модели и что даёт каждое архитектурное решение.

## Ограничения проекта

Приняты сознательно, чтобы код оставался читаемым как объяснение алгоритма:

| Ограничение | Почему |
|---|---|
| **C++14**, только стандартная библиотека | никаких Eigen, BLAS, protobuf, JSON-библиотек |
| **Один поток** | конкурентность маскирует ошибки в математике недетерминизмом |
| **Без SIMD-интринсиков** | ручное микроядро прячет алгоритм за упаковкой панелей; векторизацию оставляем `-O3` |
| **Предупреждения — ошибки** | `-Wall -Wextra -Werror` |
| **Ускорение только алгоритмическое** | кэш-блокировка, KV-кэш, слитая cross-entropy, отсутствие лишних копий |
| **Без флагов архитектуры** | базовый x86-64: ни `-march=native`, ни `-mavx2` |

Производительность ограничена сверху одним ядром, поэтому основной рабочий
пресет модели — самый маленький.

## Архитектура модели

```
tok_emb → L × [ x += attn(rms_norm(x)) ; x += ffn(rms_norm(x)) ] → rms_norm → lm_head
attn: QKV без bias → RoPE(q, k) → GQA → causal softmax → O
ffn:  SwiGLU: silu(W1·x) ⊙ (W3·x) → W2
```

Pre-norm, RMSNorm, RoPE, GQA, SwiGLU, без bias, tied embeddings.

`nano` — рабочая лошадка для экспериментов, `tiny` — прогон на вечер.

## Этапы

- [x] **M0. Скелет.** CMake, `Span`, `StrView`, выровненный `Storage`, проверки, тестовый фреймворк, CI.
- [x] **M1. Тензор и ядра.** `Shape` с broadcast, `Tensor` с шагами и видами без копирования, `Rng`, GEMM с упаковкой панелей, `matmul`, бенчмарк.
- [x] **M2. Автоград.** Лента вычислений, backward для всех операций, численная проверка градиентов.
- [x] **M3. Токенизатор.** Byte-level BPE: обучение словаря, encode/decode, roundtrip-тест.
- [x] **M4. Модель.** Forward: RMSNorm, RoPE, GQA, SwiGLU. Тест каузальности.
- [x] **M5. Обучение.** AdamW, warmup + cosine, клиппинг градиента, чекпоинты, overfit-тест.
- [x] **M6. Инференс.** KV-кэш, сэмплирование (temperature / top-k / top-p), CLI.
- [x] **M7. Архитектурная лаборатория.** Абляции: LayerNorm/RMSNorm, RoPE/обучаемые позиции/без них, GELU/SwiGLU, MHA/GQA/MQA, pre-norm/post-norm, tied/untied — с повторами по зёрнам и измеренным порогом различимости.
- [x] **M8. LoRA.** Дообучение низкоранговыми адаптерами, с измеренными границами применимости.
- [ ] Необязательный хвост: квантизация int8/q4, чтение safetensors и GGUF.

## Как оно устроено

На входе — **обычный текстовый файл**, любой. На выходе — текст в его стиле.
Ни GPU, ни Python, ни предобученных весов не нужно.

```sh
./build/bpe_train  корпус.txt  словарь.bpe  1024          # словарь
./build/train      корпус.txt  словарь.bpe  nano 2000 16  # модель
./build/generate   nano.llmw   словарь.bpe  "ROMEO:"      # текст
```

### Слои снизу вверх

**`core` — тензор.** Форма плюс шаги по осям, данные через общий буфер с
выравниванием на кэш-линию. Отсюда главное свойство: `transpose`, `reshape`,
`slice`, `expand` не копируют данные, а по-новому описывают ту же память.
Внимание пользуется этим постоянно — произведение запросов на ключи не
материализует транспонированные ключи. Здесь же `Shape` с правилами broadcast,
`Span` и `StrView` (замены `std::span` и `std::string_view`, которых нет в
C++14) и генератор случайных чисел с собственными распределениями.

**`ops` — ядра вычислений.** Перемножение матриц в двух версиях: наивный
тройной цикл как вечный эталон для тестов и блочная версия с упаковкой
панелей. Поверх — поэлементные операции с растяжением, редукции, RMSNorm и
LayerNorm, softmax, SiLU и GELU, каузальная маска, эмбеддинги, RoPE и слитая
перекрёстная энтропия. Ядра ничего не знают про градиенты и тестируются сами
по себе.

**`autograd` — лента.** Каждая операция, кроме значения, кладёт в граф
замыкание, умеющее превратить градиент по выходу в градиенты по входам.
Замыкание, а не иерархия классов: оно само захватывает всё нужное обратному
проходу, и новая операция добавляется одной функцией. Обратный проход идёт в
обратном постпорядке обхода в глубину — это топологический порядок, в котором
узел обрабатывается только после того, как все потребители внесли вклады — и
освобождает промежуточные градиенты по дороге.

**`nn` — модель.** Llama-style трансформер: RMSNorm, RoPE, GQA, SwiGLU,
пре-нормировка, связанные эмбеддинги. Все эти решения переключаются в
конфигурации, потому что в M7 их пришлось сравнивать между собой. Здесь же
KV-кэш и низкоранговые адаптеры.

**`tokenizer` — byte-level BPE.** Режет текст на куски (слово с ведущим
пробелом, число, знак препинания, пробельный пропуск) и жадно сливает самые
частые пары. Алфавит байтовый, поэтому представим любой текст и токен для
неизвестного символа не нужен вообще.

**`train` — обучение.** AdamW с разогревом и косинусным затуханием, обрезка
градиента по глобальной норме, чекпоинты, цикл с телеметрией.

**`infer` — генерация.** KV-кэш, сэмплирование с температурой, top-k, top-p и
штрафом за повтор.

### Путь одного батча

1. Датасет вырезает `batch` случайных окон длины `seq` из корпуса в токенах.
2. Эмбеддинги превращают идентификаторы в векторы: `(batch, seq, d_model)`.
3. Каждый блок: нормировка → внимание → сложение с остатком → нормировка →
   FFN → сложение с остатком. Внутри внимания проекции дают запросы, ключи и
   значения, RoPE поворачивает первые два, головы ключей размножаются под
   головы запросов, каузальная маска закрывает будущее.
4. Финальная нормировка, умножение на транспонированную таблицу эмбеддингов —
   получаются логиты `(batch, seq, vocab)`.
5. Каждая позиция предсказывает следующую; последняя отбрасывается.
6. Перекрёстная энтропия даёт скаляр, от него идёт обратный проход, AdamW
   делает шаг.

## Первый настоящий прогон

Пресет `nano` на TinyShakespeare, словарь 1024, батч 16 x 64, 2000 шагов —
18.2 минуты на одном ядре (замер предсказывал 18).

| | потери | перплексия |
|---|---|---|
| в начале | 6.944 | 1037 |
| на обучающих в конце | 3.612 | 37 |
| на проверочных в конце | 3.792 | 44 |

Начальное значение совпадает с `log(1024) = 6.93`: необученная модель
предсказывает равномерно, как и должна.

Расхождение обучающих и проверочных потерь всего 0.18 — переобучения нет.
Модель увидела 2.05 млн токенов при обучающей части в 411 тысяч, то есть
примерно пять проходов по корпусу, и на такой продолжительности запоминать
ещё нечего.

Норма градиента выросла с 1.0 до 2.3 по ходу обучения и ни разу не сорвалась;
обрезка при пороге 1.0 работала постоянно, но плавно.

```
шаг     50  потери 6.50   норма 1.04
шаг    450  потери 4.48   норма 1.22
шаг    850  потери 3.74   норма 1.71
шаг   1250  потери 3.67   норма 2.04
шаг   1650  потери 3.56   норма 2.25
шаг   2000  потери 3.61   норма 2.30
```

### Что она пишет

Затравка `ROMEO:`, температура 0.5:

```
ROMEO:
O, we'll be so?

KING RICHARD II:
Well, I will not.

KING HENRY VI:
Ank, my lord. But, I'll not my lady!

POMPEY:
```

Затравка `KING RICHARD:`, температура 0.8:

```
KING RICHARD:
And I are the grise of a crivit
That he hath danger and could cousin 'tis no
And intently throne, I'll not not to me,
Well him, in their sistering stra
```

Модель на 0.87 миллиона параметров выучила форму пьесы: реплика начинается с
имени персонажа в верхнем регистре с двоеточием, дальше идут стихотворные
строки, между репликами пустая строка. Имена настоящие — они есть в корпусе.
Подхвачены архаизмы: `hath`, `'tis`, `I'll not`. Слова вроде `grise` и
`crivit` английскими не являются: на таком размере модель знает, как слово
выглядит, но ещё не знает, какие слова бывают.

При температуре 0.5 текст грамматичнее, но однообразнее; при 0.8 разнообразнее
и бессвязнее. Это и есть то, чем температура управляет.

### Что даёт KV-кэш

61 токен при контексте 64: **811 токенов/с с кэшем против 181 без**, ускорение
4.5x. Выигрыш растёт с длиной контекста — без кэша работа на генерацию n
токенов квадратична по n, с кэшем линейна.

## Телеметрия обучения

Потери говорят, насколько модель ошибается, но ничего не говорят о том, что
внутри неё происходит. По ходу обучения печатается вот это:

```
шаг   1000/2000 [==========          ]  потери 3.7162  перпл  41.1  точность 24.4%  энтропия 4.339
                                 норма∇ 1.412  шаг/вес 1.2e-03  скорость 1.88e-04  2180 ток/с  11.4 GFLOPS  осталось 8.9 мин

  --- диагностика ---
  проверочные потери 3.9990  перплексия 54.5  расхождение с обучающими +0.283

  слой   норма∇    RMS остатка   внимание   вентили
  0      0.5253    0.0442        0.755      51%
  1      0.4215    0.0611        0.854      57%
  2      0.3356    0.0757        0.854      56%
  3      0.3089    0.0966        0.596      56%
  энтропия внимания: 1 — равномерно, 0 — сосредоточено; вентили — доля открытых каналов

  потери по четвертям окна: 4.05 / 3.99 / 3.97 / 3.97   выигрыш от контекста +0.081
```

**Отношение шага к весу** полезнее нормы градиента: норма говорит, насколько
велик градиент сам по себе, а это — насколько велик он относительно того, что
двигает. У здорового обучения держится около 1e-3. Берётся медиана по
параметрам: у одного-двух отношение бывает на порядки больше, и среднее
говорило бы только о них.

**Относительная энтропия внимания** — энтропия строки softmax, делённая на
максимальную для неё. Нормировка обязательна: ранние позиции видят меньше
ключей, и без неё величина говорила бы о длине контекста, а не о поведении
головы.

### Что видно за прогон

Пресет `nano`, 2000 шагов:

| шаг | провер. потери | точность | энтропия внимания по слоям | выигрыш от контекста |
|---|---|---|---|---|
| 200 | 4.992 | 13.8% | 0.962 0.966 0.950 **0.754** | +0.000 |
| 600 | 4.285 | — | 0.817 0.902 0.922 **0.617** | +0.064 |
| 1000 | 3.999 | 24.4% | 0.755 0.854 0.854 0.596 | +0.081 |
| 1400 | 3.863 | — | 0.717 0.825 0.812 0.590 | +0.107 |
| 2000 | 3.792 | 25.0% | 0.706 0.797 0.783 **0.578** | +0.112 |

**Энтропия внимания падает монотонно во всех слоях** — это специализация голов,
видимая числом. Последний слой сосредоточен сильнее прочих с самого начала
(0.754 против 0.96 у первых на шаге 200) и остаётся таким до конца.

**Выигрыш от контекста растёт с нуля до +0.11.** На двухсотом шаге модель
предсказывает конец окна ровно так же, как начало, то есть контекстом не
пользуется вообще. К концу разница между первой и последней четвертью окна
становится устойчивой.

Эта величина сначала была сделана неправильно: считалась на одном обучающем
батче и скакала от −0.15 до +0.27 без всякой системы. Шум полностью съедал
сигнал, и сравнивать значения в разных точках обучения было нельзя. Теперь она
снимается с проверочной выборки и усредняется по всем её батчам — выборка
фиксированная, поэтому значения воспроизводимы и сравнимы.

**RMS остаточного потока** растёт с глубиной (0.044 → 0.097) и остаётся
устойчивым по ходу обучения: поправка на инициализацию выходных проекций
работает, дрейфа нет.

## Архитектурная лаборатория

Ради этого всё и затевалось. Каждый вариант отличается от базового ровно одним
решением, обучается с одинаковым бюджетом и сравнивается по перплексии на одной
и той же проверочной выборке. Каждый прогнан **двумя зёрнами** — без этого
таблица бессмысленна, потому что непонятно, что считать различием, а что
разбросом.

Пресет `ablation` (403k параметров), 1000 шагов, батч 16 x 64, TinyShakespeare.
Порядок данных одинаков у всех прогонов, меняется только инициализация.

```sh
./build/ablate data/tinyshakespeare.txt data/shakespeare-1024.bpe 1000 2
```

| вариант | параметров | потери | разброс | перплексия | Δ к базе |
|---|---|---|---|---|---|
| несвязанные эмбеддинги | 501408 | 4.2373 | 0.0033 | 69.2 | **−0.195** |
| связанные + шире FFN | 500736 | 4.4028 | 0.0174 | 81.7 | −0.030 |
| LayerNorm | 403776 | 4.4222 | 0.0074 | 83.3 | −0.010 |
| MHA (4 головы ключей) | 430752 | 4.4302 | 0.0054 | 83.9 | −0.002 |
| **базовый (Llama-style)** | 403104 | 4.4324 | 0.0138 | 84.1 | — |
| FFN с GELU | 403104 | 4.4386 | 0.0035 | 84.7 | +0.006 |
| MQA (одна голова ключей) | 389280 | 4.4558 | 0.0039 | 86.1 | +0.023 |
| без позиций | 403104 | 4.5100 | 0.0031 | 90.9 | +0.078 |
| обучаемые позиции | 409248 | 4.5636 | 0.0017 | 95.9 | +0.131 |
| пост-нормировка | 403104 | 4.6345 | 0.0122 | 103.0 | **+0.202** |

**Порог различимости ≈ 0.02.** Разброс по зёрнам у разных вариантов лежит в
диапазоне 0.0017–0.0174; оценка по двум зёрнам сама груба, поэтому честная
формулировка не «порог ровно такой-то», а «различия порядка 0.02 на этих данных
не интерпретируются».

### Что из этого следует

**Три развилки из шести не дают ничего.** LayerNorm против RMSNorm (−0.010),
MHA против GQA (−0.002), SwiGLU против GELU при равном числе параметров
(+0.006) — все три внутри шума. Это не «ничего не выяснили», это результат:
RMSNorm и GQA оказываются бесплатными упрощениями. RMSNorm считает одну
редукцию вместо двух и не хранит свободный член; GQA вдвое уменьшает KV-кэш.
Обе экономии достались даром.

Про SwiGLU важна оговорка: выигрыш от него описывают на моделях в тысячи раз
больших. На 403k параметрах его нет — что говорит не о бесполезности вентиля,
а о том, что на этом масштабе проверить его нельзя.

**Пост-нормировка — худшая, с отрывом в десять порогов.** Ровно то, из-за чего
от неё отказались: нормировка стоит на пути остатка, и градиент на каждом слое
проходит через неё. На трёх слоях это уже стоит 0.2 по функции потерь.

**Обучаемые позиции хуже, чем полное отсутствие позиционного кодирования.**
Самый неожиданный результат таблицы: +0.131 против +0.078, оба зерна согласны
(разброс 0.0017). Правдоподобное объяснение: таблица позиций инициализируется
случайно и вносит в эмбеддинги шум, который ещё надо научиться убирать, а за
1000 шагов каждая из 64 строк получает мало сигнала. У RoPE учить нечего —
обучаемых весов нет вовсе. Оговорка: при долгом обучении картина может
измениться, и этот вывод — про короткий бюджет.

**Каузальная маска сама даёт много порядка.** Без всякого позиционного
кодирования модель теряет всего 0.078 — заметно, но далеко не катастрофа.
Внимание симметрично по позициям, и единственное, что задаёт порядок, — запрет
смотреть вперёд. Этого хватает, чтобы дойти до перплексии 91 против 84.

**MQA стоит немного, GQA — ничего.** Переход с четырёх голов ключей на две
бесплатен, с двух на одну — уже +0.023, едва выше порога. Ровно та причина, по
которой в современных моделях выбирают GQA, а не MQA.

**Развязывание эмбеддингов помогает, и не количеством весов.** Первая версия
таблицы отвечала не на тот вопрос: развязывание добавляет 24% параметров, и
выигрыш мог быть выигрышем размера. Поэтому добавлен вариант, где те же лишние
веса потрачены на ширину FFN при связанных эмбеддингах. При одинаковых ~501k
параметров развязывание даёт 4.2373, а расширенный FFN — 4.4028: разница 0.166,
на порядок больше порога. Значит одна матрица, обслуживающая сразу две роли —
представление токена на входе и различение токенов на выходе, — при словаре
1024 и d_model 96 действительно тесна.

Это не отменяет практики связывать эмбеддинги в маленьких моделях: там экономия
параметров важнее качества. Но сама по себе связка — компромисс, а не улучшение.

### Границы применимости

Всё измерено на 403k параметров, 1000 шагов (около 2.5 проходов по корпусу),
одном корпусе английской драматургии, двумя зёрнами. Каждое из этих чисел
ограничивает выводы: пропорции могут измениться и с размером модели, и с длиной
обучения, и с языком. Таблица говорит, что происходит **здесь**, — и это
по-прежнему больше, чем даёт пересказ статей.

## Дообучение адаптерами

Модель, обученную на Шекспире, дообучаем на исходниках самого проекта —
предельный сдвиг домена: C++ с русскими комментариями вместо белого стиха.

| | обучаемых | потери на новом корпусе | что пишет после `void ` |
|---|---|---|---|
| до дообучения | — | 10.08 | `ANA:\nFoubted, the chase-cladly...` |
| LoRA, ранг 8 | 14336 (**1.6%**) | 4.60 | мусор и отступы |
| полное | 869504 (100%) | **2.13** | `= 0;` |

Полное дообучение переучилось настолько, что пишет узнаваемый C++. LoRA взяла
69% улучшения по функции потерь при 1.6% обучаемых параметров, но связного
текста не даёт.

Почему — видно из замера областей применения адаптеров:

| область | обучаемых | потери |
|---|---|---|
| q+v, ранг 8 | 14336 (1.6%) | 4.600 |
| q+k+v+o, ранг 8 | 28672 (3.2%) | 4.358 |
| q+v+FFN, ранг 8 | 60416 (6.5%) | 3.937 |
| q+k+v+o+FFN, ранг 32 | 299008 (25.6%) | 3.813 |
| полное дообучение | 869504 (100%) | 2.126 |

Расширение области помогает, но упирается в потолок: с 6.5% до 25.6%
обучаемых выигрыш всего 3.94 → 3.81, а до 2.13 не доходит и близко. Дело не
только в ёмкости адаптеров. Таблица эмбеддингов при связывании служит и
выходной проекцией, и она заморожена — значит модель не может перенацелить
само распределение выдаваемых токенов, сколько адаптеров ни навешивай.

### Две границы применимости

**Адаптеры приспосабливают выученное, но не создают его.** На случайно
инициализированной модели те же адаптеры упираются в плато: всё замороженное
там не признаки, а шум, и опереться не на что. На предобученной модели 896
параметров адаптеров доводят потери на новой задаче с 13.9 до 0.002 — как
полное дообучение с 16544 параметрами. Разница между этими двумя случаями
измерена и закреплена тестами.

**Предельный сдвиг домена адаптерам не по силам.** Они меняют то, как модель
смотрит на контекст, а не то, какими токенами она оперирует.

## Производительность GEMM

Замеры на одном ядре, задача 512x512x512, GCC 13 и clang 18 дают одинаковые
цифры:

| вариант | GFLOPS | к наивному |
|---|---|---|
| наивный тройной цикл | 1.5 | 1x |
| блочный, вложенный цикл в микроядре | 3.8 | 2.5x |
| блочный, развёрнутое микроядро 4x32 | **21** | **14x** |
| то же, сборка с `-mavx2 -mfma` | 54 | 36x |

Два наблюдения из этих замеров стоят того, чтобы их записать.

**Форма микроядра важнее ширины векторов.** Переход от вложенного цикла по
строкам плитки к ручной развёртке дал 5.5x, тогда как разрешение компилятору
использовать AVX2 вместо SSE2 — всего 1.05x на том же вложенном цикле. Причина
в том, что при вложенном цикле GCC не разворачивает внешний цикл, аккумуляторы
остаются в стеке, и каждое умножение становится парой обращений к памяти. При
этом clang разворачивает и вложенную форму, а у GCC разница между плитками
4x16 и 4x32 доходила до двадцати раз. Развёрнутая вручную форма убирает эту
зависимость от версии компилятора: оба компилятора дают одинаковый результат.

**AVX-512 медленнее AVX2.** На этой машине `-mavx512f` даёт 35 GFLOPS против
54 у `-mavx2 -mfma`, поэтому `-march=native`, включающий AVX-512, оказывается
хуже явного указания AVX2.

Строка с `-mavx2 -mfma` приведена только как замер: **проект собирается под
базовый x86-64 и никаких флагов архитектуры не включает.** Решение осознанное —
никаких предположений о процессоре, на котором собирается код. Цена известна и
принята: всё обучение идёт примерно вдвое дольше.


## Как проверяется корректность

Эталонной реализации под рукой нет (ни PyTorch, ни NumPy), поэтому тесты
устроены так, чтобы ловить ошибки без внешнего эталона:

1. **Численная проверка градиентов** — центральная разность для каждой операции. Допуск 1e-3 подобран замером: на верном коде расхождение лежит в диапазоне 2e-6..7.6e-5, а внесённая ошибка в 5% даёт 0.03, то есть обнаруживается с тридцатикратным запасом.
2. **Оптимизированное против наивного** — блочный GEMM сверяется с тривиальным тройным циклом, который остаётся в коде навсегда. Слитые ядра RMSNorm и softmax сверяются со сборкой той же формулы из примитивов — и по значению, и по градиентам.
3. **Тест каузальности** — изменение токена на позиции *t* не должно менять логиты на позициях < *t*, причём **побитово**: закрытые позиции получают ровно нуль после экспоненты минус бесконечности, и умножение на нуль даёт нуль независимо от того, что изменилось. Одним тестом покрывает маску, RoPE, перестановки голов и направление умножения запросов на ключи.
4. **KV-кэш ≡ полный пересчёт** — генерация с кэшем совпадает с генерацией без него **побитово**, на каждом шаге и по всем логитам. Кэш не приближает вычисление, а лишь избавляет от его повторения, поэтому расхождение даже в последнем бите означало бы ошибку: сдвинутые позиции RoPE, неверное смещение маски или испорченную раскладку голов.
5. **Overfit одного батча** — loss должен уйти к нулю; иначе сломан оптимизатор или градиенты.
   Плюс: потери необученной модели обязаны быть около `log(vocab_size)` — необученная модель ничего не знает и предсказывает почти равномерно. Отклонение означало бы, что инициализация выбивает логиты из рабочего диапазона ещё до обучения.
6. **BPE roundtrip** — `decode(encode(x)) == x` побайтово: на корпусе обучения, на невиданном тексте, на всех 256 значениях байта и на случайном мусоре. Байтовый алфавит замкнут, поэтому непредставимого входа не бывает в принципе.

Сборка идёт в четырёх конфигурациях CI (gcc и clang × Release и Debug+ASan):
Release проверяет ветку макросов с `NDEBUG`, Debug — с активными `LLM_DCHECK`.

## Соглашения

Комментарии на русском и объясняют **почему**, а не пересказывают код: проект
пишется как объяснение, а не как продакшен-библиотека.

`LLM_CHECK*` активны всегда, включая Release, — для ошибок логики.
`LLM_DCHECK*` только в Debug — для горячих мест вроде индексации тензоров.
