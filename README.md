# LLM на C++14 с нуля

Учебная реализация языковой модели современной архитектуры (Llama-style) без
внешних зависимостей. Цель — не догнать llama.cpp по скорости, а разобраться,
из чего состоят современные модели и что даёт каждое архитектурное решение.

## Ограничения проекта

Приняты сознательно, чтобы код оставался читаемым как объяснение алгоритма:

| Ограничение | Почему |
|---|---|
| **C++14**, только стандартная библиотека | никаких Eigen, BLAS, protobuf, JSON-библиотек |
| **Один поток** | конкурентность маскирует ошибки в математике недетерминизмом |
| **Без SIMD-интринсиков** | ручное микроядро прячет алгоритм за упаковкой панелей; векторизацию оставляем `-O3` |
| **Предупреждения — ошибки** | `-Wall -Wextra -Werror` |
| **Ускорение только алгоритмическое** | кэш-блокировка, KV-кэш, слитая cross-entropy, отсутствие лишних копий |

Производительность ограничена сверху одним ядром, поэтому основной рабочий
пресет модели — самый маленький.

## Архитектура модели

```
tok_emb → L × [ x += attn(rms_norm(x)) ; x += ffn(rms_norm(x)) ] → rms_norm → lm_head
attn: QKV без bias → RoPE(q, k) → GQA → causal softmax → O
ffn:  SwiGLU: silu(W1·x) ⊙ (W3·x) → W2
```

Pre-norm, RMSNorm, RoPE, GQA, SwiGLU, без bias, tied embeddings.

## Пресеты

| пресет | d_model | L | heads / kv | ctx | vocab | параметров | шаг | 2000 шагов |
|---|---|---|---|---|---|---|---|---|
| `nano` | 128 | 4 | 4 / 2 | 64 | 1024 | 0.87M | ~0.7 с | ~25 мин |
| `tiny` | 256 | 4 | 8 / 2 | 128 | 4096 | 3.9M | ~6 с | ~3 часа |
| `small` | 384 | 6 | 6 / 2 | 256 | 8192 | 12.6M | ~40 с | ~21 час |

Оценки времени — прикидка до замеров на M1, точность порядка ±3x. `nano` —
рабочая лошадка для экспериментов, `tiny` — ночной прогон.

## Этапы

- [x] **M0. Скелет.** CMake, `Span`, `StrView`, выровненный `Storage`, проверки, тестовый фреймворк, CI.
- [ ] **M1. Тензор и ядра.** shape/stride, view/reshape/transpose, broadcast, GEMM с кэш-блокировкой, бенчмарк.
- [ ] **M2. Автоград.** Лента вычислений, backward для всех операций, численная проверка градиентов.
- [ ] **M3. Токенизатор.** Byte-level BPE: обучение словаря, encode/decode, roundtrip-тест.
- [ ] **M4. Модель.** Forward: RMSNorm, RoPE, GQA, SwiGLU. Тест каузальности.
- [ ] **M5. Обучение.** AdamW, warmup + cosine, клиппинг градиента, чекпоинты, overfit-тест.
- [ ] **M6. Инференс.** KV-кэш, сэмплирование (temperature / top-k / top-p), CLI.
- [ ] **M7. Архитектурная лаборатория.** Абляции: LayerNorm/RMSNorm, RoPE/обучаемые позиции, GELU/SwiGLU, MHA/GQA/MQA, pre-norm/post-norm, tied/untied, sliding window, MoE.
- [ ] **M8. LoRA.** Дообучение низкоранговыми адаптерами.
- [ ] Необязательный хвост: квантизация int8/q4, чтение safetensors и GGUF.

## Сборка

```sh
# Release
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure

# Debug с ASan и UBSan (здесь активны LLM_DCHECK)
cmake -S . -B build-debug -DCMAKE_BUILD_TYPE=Debug -DLLM_SANITIZE=ON
cmake --build build-debug -j
ctest --test-dir build-debug --output-on-failure
```

Отдельный запуск набора: `./build/llm_tests Storage`.

## Как проверяется корректность

Эталонной реализации под рукой нет (ни PyTorch, ни NumPy), поэтому тесты
устроены так, чтобы ловить ошибки без внешнего эталона:

1. **Численная проверка градиентов** — центральная разность для каждой операции, относительная ошибка < 1e-4.
2. **Оптимизированное против наивного** — блочный GEMM сверяется с тривиальным тройным циклом, который остаётся в коде навсегда.
3. **Тест каузальности** — изменение токена на позиции *t* не должно менять логиты на позициях < *t*. Одним тестом покрывает маску, RoPE и форму attention.
4. **KV-кэш ≡ полный пересчёт** — генерация с кэшем совпадает с генерацией без него.
5. **Overfit одного батча** — loss должен уйти к нулю; иначе сломан оптимизатор или градиенты.
6. **BPE roundtrip** — `decode(encode(x)) == x` побайтово на всём корпусе.

Сборка идёт в четырёх конфигурациях CI (gcc и clang × Release и Debug+ASan):
Release проверяет ветку макросов с `NDEBUG`, Debug — с активными `LLM_DCHECK`.

## Соглашения

Комментарии на русском и объясняют **почему**, а не пересказывают код: проект
пишется как объяснение, а не как продакшен-библиотека.

`LLM_CHECK*` активны всегда, включая Release, — для ошибок логики.
`LLM_DCHECK*` только в Debug — для горячих мест вроде индексации тензоров.
